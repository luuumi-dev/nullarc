# Known Issues — nullarc (RDNA3 on macOS)

Эталонная платформа: Firebat U6C (AMD Ryzen 7 7840HS / H 255, Radeon 780M / RDNA3 gfx1103, macOS Sequoia / Tahoe 26.6.2).
Репозиторий: `luuumi-dev/nullarc` (локально: `rdna3-driver`).

---

## 1. Критические проблемы (S1)

### [B-32] Падение приложений из-за исчерпания памяти (UMA reserve / VRAM buffer sprawl)
- **Симптомы**: Приложения (Telegram, UserNotificationCenter) падают с `SIGBUS: FS pagein error: 94 Bad message` при обращении к общим библиотекам (например, `liblangid.dylib`). Своп забит (8.9 / 9.2 ГБ), `kernel_task` раздут до 14+ ГБ.
- **Причина**:
  1. 6.4 ГБ системной RAM наглухо зарезервировано под UMA GPU в BIOS, хотя драйвер использует первые ~128 МБ (PSP ring, TMR 20 МБ, firmware 64 МБ).
  2. Буферы Metal в `PhxBringup` удерживают по 70–80 МБ wired memory на каждый процесс (50 клиентов = ~4 ГБ).
  3. `nvmtl_desc_pool_open` открывал сразу по 32–36 МБ пула дескрипторов на процесс с первого draw call.
- **Статус**: В работе / частичный обход.
  - В `nvmtl_vk.c`: динамический рост пулов (256 сетов -> удвоение до 4096), staging buffer ограничен 4 МБ вне WindowServer.
  - Требуется: уменьшить UMA в BIOS до 1 ГБ (через меню или NVRAM/ACPI).

### [B-30] Зависание GPU при OpenCL / Compute вычислениях (Geekbench 6 Feature Matching)
- **Симптомы**: Сложные compute-ядра вешают очередь GPU. Без аппаратного GPU reset зависание одной очереди подвешивает весь WindowServer, срабатывает сторожевой таймер macOS, система падает в ребут.
- **Причина**: Отсутствие soft-recovery и изоляции очередей в `PhxBringup`.
- **Статус**: Нужна проверка на железе.
  - В `PhxBringup` (build 34) добавлен watchdog: если очередь не продвигает fence дольше `debug.phx_hang_ms` (3000 мс), через RLC safe mode в `SQ_CMD` посылается broadcast kill волн зависшего VMID. `hangprobe` успешно сбрасывает зависшие волны без падения WindowServer.

## 2. Серьёзные функциональные дефекты (S2)

### [B-08] Сон и поведение при закрытии крышки (Sleep / Clamshell / DarkWake)
- **Симптомы**: Ноутбук не уходит в полноценный сон при закрытии крышки или через меню Apple. Экран гаснет, но система остаётся в DarkWake (кулеры крутятся, процессор греется). При форсировании S3 через DSDT зависает намертво при пробуждении.
- **Причина**:
  1. В BIOS Firebat U6C отсутствует рабочий S3 (`_S3` переименован в `XS3`, переменная `SS3 = 0`). Платформа поддерживает только Modern Standby (S0ix) / S4 (Hibernation).
  2. Без DSDT-патча `AppleACPIPlatform` блокирует переход в сон ошибкой `kPMPCIUnsupported`.
  3. Драйверы `PhxBringup` и `PhxAMDFB` не зарегистрированы в Power Management (`IOService::PMinit`, `registerPowerDriver`), не обрабатывают смену питания (`setPowerState`). При выходе из сна BAR0, кольца MES/KIQ и регистры GPU сброшены, что приводит к Kernel Panic или зависанию без сети.
- **Статус**: В работе (детальный план см. в архитектурном разделе ниже).

### [B-02] Белые вспышки и артефакты при системных алертах
- **Симптомы**: Белое свечение или мусор в верхней строке при нажатии Ctrl+C, попытке клика по неактивному окну.
- **Причина**: При отсутствии аудиовыхода macOS визуализирует алерты морганием экрана через CoreDisplay. На DCN-плоскости без аппаратного LUT это вызывало артефакты.
- **Статус**: Нужна проверка (звук поднят в B-03, алерт перестал дергать экран).

### [B-24] Низкий FPS в 3D / OpenGL приложениях (Шахматы и др.)
- **Симптомы**: OpenGL-игры и утилиты выдают 30–60 FPS с высоким потреблением CPU.
- **Причина**: `IOSurface` OpenGL имеет шаг строки 9600 байт (не кратно 256), из-за чего кадрирование шло через CPU копирование 14 МБ. Кроме того, 43% времени OpenGL ждёт синхронного `SLSFlushSurface` от WindowServer.
- **Статус**: В работе. Копирование переведено на GPU blit через страницы поверхности (падение времени с 13 мс до 0.45 мс). Ожидается устранение задержек очереди.

### [B-25] Высокая нагрузка UE200 USB-Ethernet
- **Симптомы**: USB-сетевая карта RTL8153 потребляет 1.5 ядра CPU (`AppleUserECM` ~79%, `kernel_task` ~67%, ~14k прерываний/с на XHC0).
- **Причина**: Постоянный polling / активный трансфер драйвера ECM в macOS Sequoia/Tahoe.
- **Статус**: Открыт. Обход — отключение адаптера при стабильном Wi-Fi.

### [B-29] Сбои трансляции Metal2Vulkan в Geekbench 6 Metal (MPSGraph)
- **Симптомы**: Geekbench 6 Metal падает на тесте Background Blur (`depthwiseConv_3x3`).
- **Причина**: Closed-source транслятор `metal2vulkan` (NullMoth) не поддерживает объединение указателей Function vs Private storage в LLVM IR (`pointer merge storage mismatch`).
- **Статус**: Открыт. Требуется либо доработка самого транслятора, либо трансляция через SPIR-V LLVM translation layer.

## 3. Средние и косметические проблемы (S3 / S4)

### [B-01] Подключение USB-C устройств
- **Симптомы**: При физическом подключении кабеля USB-C (iPhone и др.) система подвисает на 20–30 секунд.
- **Причина**: EC шлет ACPI-событие, вызывая метод `\_SB.ALIB(0x0C)`. В DSDT метод падал с ошибкой `AE_AML_NO_RETURN_VALUE` (5 раз подряд), после чего macOS параллельно запускает сервисы синхронизации устройств.
- **Статус**: Исправлено в `hardware/acpi/SSDT-ALIB.dsl` (.aml) — метод 0x0C возвращает Zero под Darwin.

### [B-07] Отображение статуса Wi-Fi
- **Симптомы**: Wi-Fi работает стабильно через `AirportItlwm 2.4.0`, но сетевой апплет пишет «Network Service Inactive» / «Ethernet». AirDrop и Handoff недоступны из-за ограничений Intel AX210 на версиях macOS 26.5+.

### [B-28] Рывки курсора при включении Night Shift
- **Симптомы**: При плавном включении/выключении Night Shift курсор подергивается в течение 2–3 секунд.
- **Причина**: Отсутствие аппаратного LUT гаммы в `PhxAMDFB`. `CoreDisplay` программно просчитывал LUT для плоскости через `dispatch_apply` на всех ядрах CPU.
- **Статус**: Исправлено в `src/phxaccel/accel/phxfb.cpp` (`getGammaTableCapabilities` и `getGammaTable`).

### [B-10] Отсутствие аппаратного ускорения видео (VCN)
- **Симптомы**: YouTube 4K / декодирование h.264/HEVC/AV1 полностью ложится на CPU.
- **Причина**: Блок VCN 4.0.2 не инициализирован в `PhxBringup` и не связан с Apple VideoToolbox.

### [B-11] Внешние дисплеи (HDMI / Type-C DP)
- **Симптомы**: Внешние мониторы не выводят изображение.
- **Причина**: `PhxAMDFB` настроен только на встроенную eDP-панель. Дополнительные DCN-пайплайны и PHY не сконфигурированы.
- **Статус**: В работе. Интегрированы модули DCN 3.1.4 и DMUB от Kreytus (`src/amd/phx_dcn314_*`, `phx_dmub_*`).

### [B-33] Крэш обоев симулятора iOS (MercuryPosterExtension)
- **Симптомы**: Симулятор каждые несколько минут выдает SIGFPE в `MTLSimDriver` (деление на 0 в `copyFromBuffer:sourceBytesPerRow:`).
- **Причина**: Отсутствовал метод `-minimumTextureBufferAlignmentForPixelFormat:`.
- **Статус**: Исправлено в `src/nmplugin/NVMTLDevice.m` (возвращает выравнивание 256), собрано и установлено на эталонный Mac.

## 4. Архитектурный план: Починка сна (B-08)

### Диагностика ограничений платформы Phoenix / Firebat
1. **Отсутствие S3 (Suspend-to-RAM)**:
   - В ACPI таблицах Phoenix firmware переведено на современный S0ix (Modern Standby). Классический S3 выключен производителем ноутбука. При попытке включить `_S3` через OpenCore ACPI rename контроллер питания не может корректно пробудить процессорные ядра и чипсет.
2. **Путь решения: S4 Hibernation (Suspend-to-Disk / Safe Sleep)**:
   - macOS переводит память в образ `sleepimage` и выключает питание.
   - При старте OpenCore читает образ и восстанавливает контекст ядра.

### Необходимые шаги для реализации:
1. **Перехват политики сна в macOS**:
   - По умолчанию `X86PlatformPlugin` выбирает Sleep Type 7 (DeepIdle / S3 без сброса на диск).
   - Необходимо зарегистрировать собственный `IOPMSystemSleepPolicyHandler` через:
     ```cpp
     IOPMrootDomain::callPlatformFunction(kIOPMInstallSystemSleepPolicyHandlerKey, ...);
     ```
     (встраивается в Lilu-плагин, например `PhxHDA` или отдельный модуль сна), принудительно возвращая `kIOPMSleepTypeHibernate` (S4).
2. **Жизненный цикл GPU в `PhxBringup`**:
   - `PhxBringup` должен реализовать интерфейс управления питанием:
     - `PMinit()` / `registerPowerDriver()`.
     - `setPowerState(ordinal, whichDevice)`:
       - **Перед сном (Power State 0)**:
         1. Приостановка диспетчеризации новых очередей (gate submit queue).
         2. Дождаться завершения активных fence или принудительно остановить KIQ/MES.
         3. Зафиксировать последний completed sequence number.
       - **После пробуждения (Power State 1)**:
         1. Повторить инициализацию контроллера: `bringup5` -> переинициализация GART -> загрузка прошивок MES -> подъем kiqsched.
         2. Сохранить все существующие виртуальные буферы и маппинги таблиц страниц (они сохраняются в системной памяти в `sleepimage`).
         3. Перепривязать контексты очередей (adopt) и разморозить submit.
3. **Восстановление дисплея в `PhxAMDFB`**:
   - Реализовать восстановление таймингов eDP и ШИМ-контроллера подсветки после восстановления питания DCN.
   - Переинициализация DCN plane и возврат фреймбуфера без черного экрана.
